What we build

The framework treats design, execution, and analysis as one piece of work. A case, the run it belongs to, and the report that follows stay together.

Design is where a case is written against the product under test. It names the behavior, the setup, and the result that counts as a pass. When requirements or code change, the case is updated so the suite still describes the product.

A run is the record of an execution. It shows which cases were included, which passed, which failed, and which never started. That record stays attached to the cases, so a later run can be set next to an earlier one.

Analysis turns the record into something the team can read. Failures are grouped, a result that comes and goes is marked as flaky, and the rest of the run is summarized so it is clear what held. The report is that reading in a form people can share.

  • Design Behavior, setup, and the result that counts as a pass.
  • Run Pass, fail, and anything the suite did not reach.
  • Compare A new run set beside an earlier one, on the same cases.
  • Report A shareable account of what the run showed.
