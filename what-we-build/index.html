What we build

Accessibility Audit Application

A desktop app for Windows and Mac, and a command-line tool for build pipelines, that audit websites against WCAG 2.2 level A and AA.

Request early access Trial and pricing

What it checks

Six kinds of checks in one audit

Results from every source are merged, so one problem on one element is one finding, however many checks noticed it.

Keyboard

A real Tab crawl

It tabs through the page and reports controls the keyboard cannot reach, focus traps, skip links that go nowhere, missing focus indicators and focus hidden behind sticky bars.

Visual

Measured, not guessed

Contrast sampled from rendered pixels over gradients and images, 24-pixel target size, text that clips when spacing grows, sideways scrolling at 320 pixels, motion that ignores the reduced-motion setting, and audio that starts by itself.

Forms

Errors that reach everyone

It types invalid values with real keystrokes and checks that the error message is exposed to assistive technology. It never submits a form.

Screen reader

What is actually announced

Accessible names, landmarks and heading structure from the browser's accessibility tree, and on request a walkthrough with a real screen reader: NVDA on Windows, VoiceOver on Mac.

Rule engines

Two engines, checked against the page

The axe-core and IBM Equal Access rule sets run on every page. Where an engine cannot decide, the app measures the live element and closes the question only when it has proof.

Hard-to-reach pages

Behind logins and interactions

Record a journey once, including a login, and audit each step. Embedded frames and open shadow DOM are audited too.

Honest about coverage

No green tick for something nobody tested

No tool can decide all of WCAG. Of the 55 level A and AA success criteria in WCAG 2.2, the app tests the main failure modes of 19 and a named part of 16. The other 20 need a person.

The report shows this for every criterion, and the human-review checklist says what to look at and how. An audit is complete when a person has finished that list.

Where it runs

On a desk or in a pipeline

Desktop app

Windows and Mac

Start audits, watch progress, triage findings, record journeys and compare an audit with the one before it. Reports open in the app and are ordinary files you can pass on.

Command line

Any build pipeline

One command with clear exit codes, a baseline for known issues so only new problems fail a build, and results as HTML, JSON, Markdown, SARIF for code scanning, or Allure.

What it does not do

Limits we would rather state ourselves

  • It does not certify conformance. A report without findings is not a statement that a site meets WCAG or any law.
  • It does not change your site. There is no overlay or script to install. It reports; your team fixes.
  • It audits in one browser. Pages are loaded in Chromium at a desktop size. Other browsers and phone layouts are not audited yet.
